Endereços que não podem ser confundidos

  1. No navegador: Grafana http://localhost:3300 ; aplicação http://localhost:38081 ; receptor http://localhost:38090 ; Prometheus http://localhost:39090 ; Loki http://localhost:33100.
  2. Dentro do Grafana: fonte Prometheus http://prometheus:9090 ; fonte Loki http://loki:3100 ; contato Webhook http://webhook:8080/. Esses nomes são resolvidos dentro da rede Docker.
  3. localhost no navegador é o seu computador. localhost dentro de um container é aquele container. Os endereços internos não são URLs para abrir diretamente no navegador.
  4. As capturas são do Grafana 12.0.1 do pacote. A VM de demonstração do professor usa outra versão. Se um menu estiver recolhido, abra o ícone Grafana; em telas pequenas, consulte Show more items.
  5. Os exercícios são feitos manualmente. Os arquivos em exemplos-importaveis são modelos opcionais, independentes das entregas dos exercícios.

Diagnóstico rápido antes de pedir ajuda

  1. Página não abre: confira a porta correta e se os containers estão em execução. No terminal da pasta lab/tutorial-environment, execute docker ps. O serviço do lab deve aparecer em execução.
  2. Porta ocupada: não desligue projetos desconhecidos. Verifique se é uma cópia deste próprio laboratório; se for, reutilize a cópia ativa e a pasta correspondente. Alterar portas exige atualizar os endereços nos guias.
  3. No data em Prometheus: confirme a fonte, gere atividade na aplicação, espere duas coletas de 5s, confira o relógio e use Last 15 minutes. Execute novamente. Zero é um resultado numérico; No data significa ausência de amostras na consulta.
  4. No data em Loki: primeiro teste a fonte; depois confirme a consulta filename, gere uma ação na aplicação e aguarde a coleta. Remova temporariamente o filtro error para separar falha no filtro de ausência de logs.
  5. Erro de sintaxe: copie somente a expressão e substitua aspas curvas por aspas retas. PromQL pertence ao Prometheus; LogQL pertence ao Loki.
  6. Confirme cada Save: salvar painel, dashboard, fonte, contato e regra são ações distintas. Test no contato e Preview na regra não equivalem a salvar.
  7. Registre fonte, consulta, período, horário e mensagem exata do erro. Isso permite explicar o problema e reproduzir sua tentativa.

Preparar a pasta e iniciar o laboratório

  1. Baixe o ZIP completo da turma e use Extrair tudo. Guarde em uma pasta simples, por exemplo C:/CursoGrafana. Não execute arquivos dentro do ZIP.
  2. Abra a pasta que contém iniciar-lab.ps1, iniciar-lab.sh, lab e alunos. Abra o Docker Desktop e aguarde o mecanismo ficar em execução.
  3. No Windows, clique com o botão direito dentro dessa pasta e escolha Abrir no Terminal. No PowerShell, execute o comando mostrado abaixo. A pasta atual deve ser a raiz extraída do pacote.
  4. Aguarde o término do download e da construção da aplicação. O primeiro início pode levar vários minutos. Só prossiga se o script terminar sem erro e mostrar os três endereços.
  5. No Ubuntu com Docker e Compose já instalados, use bash ./iniciar-lab.sh na mesma pasta. Esta é a rota Docker; os scripts de instalação nativa no Ubuntu continuam sendo uma etapa posterior do curso.
  6. Mantenha os serviços em execução durante as cinco noites. Os passos seguintes são feitos no navegador, em três abas: Grafana, aplicação e receptor de notificações.
# Windows / PowerShell, na raiz extraída do pacote
powershell -NoProfile -ExecutionPolicy Bypass -File .\iniciar-lab.ps1

# Ubuntu com Docker e Compose já instalados
bash ./iniciar-lab.sh

Resultado esperado: O script mostra Grafana em localhost:3300, aplicação em localhost:38081 e receptor em localhost:38090.

Se não funcionar: Se docker não for reconhecido, reabra o terminal após instalar o Docker Desktop. Se houver erro de conexão com o daemon, abra o Docker Desktop. Se uma porta estiver ocupada, não encerre outros projetos: consulte a seção de diagnóstico deste guia.

Selecionar a fonte no Explore

NOITE 2 • EXERCÍCIO 2.1 • ETAPA 2

Executar e interpretar o contador

  1. Cole a consulta abaixo no editor A. Use aspas retas e copie somente a consulta, sem as marcas de bloco de código.
  2. Clique em Run query, no topo à direita, ou use Shift+Enter. Aguarde o gráfico carregar.
  3. Abra o seletor de período e use Last 15 minutes. Isso é suficiente para um laboratório recém-iniciado.
  4. Leia a legenda abaixo do gráfico. Identifique route e status_code em pelo menos duas séries.
  5. Anote que o valor representa uma contagem de requisições por combinação de labels, não CPU, tempo em segundos ou req/s.
  6. Atualize a aplicação em outra aba, aguarde aproximadamente 10 segundos e execute Run query novamente. O contador pode voltar a zero se o processo reiniciar.
tns_request_duration_seconds_count

Resultado esperado: O gráfico mostra séries do contador, com labels como route e status_code.

Se não funcionar: Em No data, confirme a fonte Prometheus, abra a aplicação, atualize-a, aguarde duas coletas de 5s e execute novamente. Um gráfico vazio à esquerda do horário de início do lab é esperado.

  2. Na lista de períodos relativos, clique no texto Last 5 minutes. O menu fecha ao aplicar a seleção.
  3. Confirme que o botão passou a mostrar Last 5 minutes.
  4. Se o período aparecer apenas como um relógio, expanda Show more items ou feche o menu lateral.
  5. Não preencha datas absolutas neste exercício. Esse período acompanha o relógio do computador e mostra a janela mais recente.

Resultado esperado: O período visível é Last 5 minutes.

Se não funcionar: Se você clicou e nada mudou, clique no texto do intervalo, não na borda da caixa. Um período absoluto não avança sozinho.

NOITE 2 • EXERCÍCIO 2.2 • ETAPA 4

Calcular a taxa por rota

  1. Substitua a consulta A pela expressão abaixo e clique em Run query.
  2. Volte à aplicação e atualize a página 10 a 15 vezes. Espere cerca de 10 segundos para que o Prometheus colete novas amostras.
  3. Volte ao Explore e clique em Run query novamente. Na legenda, localize root, post e vote, se estiverem presentes.
  4. Leia a taxa na curva. A unidade é requisições por segundo. A função rate usa as amostras dos últimos 5 minutos.
  5. Observe também a rota metrics: ela recebe as requisições de coleta do próprio Prometheus. Esse tráfego não significa que um aluno visitou a aplicação.
  6. Anote uma rota, um valor aproximado e o período. Um valor 0,05 req/s equivale, em média, a uma requisição a cada 20 segundos.
sum(rate(tns_request_duration_seconds_count[5m])) by (route)

Resultado esperado: Você identifica taxas por rota e diferencia o scrape das ações do usuário.

Se não funcionar: Taxas pequenas são normais quando você clica poucas vezes. Não espere um número igual ao print. Zero com uma série presente é diferente de No data.

NOITE 2 • EXERCÍCIO 2.3 • ETAPA 5

Comparar por status HTTP

  1. Substitua by (route) por by (status_code), usando a consulta completa abaixo.
  2. Execute Run query e leia a legenda: por exemplo 200, 302, 400 ou 404, conforme as ações já feitas.
  3. Compare: route agrupa pelo caminho lógico; status_code agrupa pelo código de resposta. A unidade continua req/s.
  4. Troque Last 5 minutes por Last 15 minutes e depois volte. A janela interna [5m] continua a mesma.
  5. Registre as duas consultas e explique, em suas palavras, a diferença entre janela do rate e período exibido.
  6. Entregue uma captura por agrupamento. A ausência de 400 é normal antes do erro que será produzido na Noite 3.
sum(rate(tns_request_duration_seconds_count[5m])) by (status_code)

Resultado esperado: Você compara as mesmas requisições usando dimensões diferentes.

Se não funcionar: Uma série nova aparece somente depois de a aplicação produzir aquela combinação de labels. Não invente erro para fazer a legenda coincidir com o print.

NOITE 3 • EXERCÍCIO 3.1 • ETAPA 4

Consultar o arquivo inteiro

  1. Cole a consulta abaixo no editor A e clique em Run query ou pressione Shift+Enter.
  2. Aguarde o resultado. Você deve ver o volume de logs e uma lista de linhas da aplicação.
  3. Se a lista estiver abaixo da área visível, role a página; você pode recolher Logs volume pelo título da seção.
  4. Leia um horário e uma mensagem. filename identifica o arquivo; job identifica o fluxo de coleta.
  5. Anote a quantidade de linhas exibida, sabendo que ela depende do período e do limite de resultados.
{filename="/var/log/tns-app.log"}

Resultado esperado: As linhas vêm de /var/log/tns-app.log e incluem eventos da aplicação.

Se não funcionar: Em No data: abra a aplicação, atualize-a, aguarde 10 a 20 segundos e execute novamente. Confira aspas, filename e período. Não use o seletor service do ambiente de e-commerce do professor neste laboratório.

NOITE 3 • EXERCÍCIO 3.2 • ETAPA 5

Produzir o erro controlado

  1. Na aba da aplicação, preencha Title com Teste sem URL - seguido do seu nome.
  2. Deixe o campo URL completamente vazio. Esta falha é intencional e limitada à aplicação de exemplo.
  3. Anote o horário e clique em Submit uma única vez.
  4. A aplicação deve mostrar empty url. Faça uma captura da mensagem.
  5. Use Voltar do navegador para retornar ao formulário. Não continue reenviando o POST ao recarregar a página de erro.

Resultado esperado: A aplicação respondeu empty url e você registrou o horário.

Se não funcionar: Se o link foi publicado, havia uma URL no campo. Volte ao formulário, limpe-a e repita uma vez. Esse erro de validação não exige reinstalar o lab.

NOITE 3 • EXERCÍCIO 3.2 • ETAPA 6

Localizar somente as linhas de erro

  1. Volte ao Explore com Loki. Substitua a consulta anterior pelo filtro abaixo.
  2. Selecione Last 15 minutes e clique em Run query. Espere a coleta se a ação acabou de ocorrer.
  3. Na lista Logs, procure a linha level=error msg="empty url".
  4. Compare o horário do log com o horário da ação no navegador. O fuso de exibição pode ser o do navegador.
  5. O operador |= procura texto e diferencia maiúsculas de minúsculas. Neste aplicativo o texto é error, em minúsculas.
{filename="/var/log/tns-app.log"} |= "error"

Resultado esperado: Você relaciona o erro provocado à linha de log correspondente.

Se não funcionar: Se não houver resultado, remova temporariamente |= "error". Se os logs voltarem, revise o texto do filtro e o período. Se Live estiver ativo, pare-o antes de abrir os detalhes.

NOITE 3 • EXERCÍCIO 3.2 / 3.3 • ETAPA 7

Abrir o evento e descrever a investigação

  1. Na linha do erro, clique na pequena seta ou no botão See log details, à esquerda da linha.
  2. Leia a mensagem e os campos filename e job. Esses campos confirmam a origem do fluxo.
  3. Compare a consulta sem filtro com a consulta contendo |= "error". A segunda deve mostrar um subconjunto da primeira no mesmo período.
  4. Mude Last 15 minutes para Last 1 hour e observe se a quantidade de linhas aumenta. Depois volte ao período curto.
  5. Entregue uma sequência reproduzível: ação feita, horário, fonte Loki, seletor, filtro e mensagem encontrada.
  6. Escreva a conclusão: a aplicação rejeitou uma URL vazia e registrou o erro. Uma coincidência temporal isolada entre eventos diferentes não prova causa.

Resultado esperado: Sua evidência inclui o erro no navegador e a linha expandida nos logs.

Se não funcionar: As linhas logfmt deste exemplo não são JSON. Não acrescente | json automaticamente. A investigação de TraceID e Tempo pertence à demonstração complementar do professor.

NOITE 5 • EXERCÍCIO 5.2 • ETAPA 5

Definir B e C sem ligar o limite à série bruta

  1. Em Expressions, localize Reduce. Se ela já existir como reducer, clique no nome, troque por B e pressione Enter. Se não existir, use Add expression > Reduce e nomeie B.
  2. Em B, configure Input = A, Function = Last e Mode = Strict. Cada série será reduzida a um valor.
  3. Localize a expressão Threshold C. Configure Input = B, Is above e limite 0.01. A tela em português pode mostrar 0,01.
  4. Depois de renomear reducer, confira novamente Input de C: algumas versões voltam para A. Reescolha B.
  5. C deve estar marcada Alert condition. Caso não esteja, use Set as alert condition na expressão C.
  6. Clique em Preview. A prévia pode mostrar Normal ou Firing, conforme o valor atual de B. Neste laboratório o limite é didático, não um limite recomendado para produção.

Resultado esperado: B tem um número por rota e C compara esse número com 0,01 req/s.

Se não funcionar: You cannot use time series data as an alert condition indica que C ainda usa A ou que B não é Reduce/Last. Corrija a referência antes de salvar. Não conclua entrega somente pela prévia.
